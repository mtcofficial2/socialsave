# SocialSave API

Go rewrite of the SocialSave backend. The Flutter app keeps the same routes and JSON: `/health`, `/api/v1/platforms`, `/api/v1/analyze`, `/api/v1/download`, `/api/v1/download/{job_id}`, and `/api/v1/files/{token}`.

A public media URL is returned as `direct_url` plus an HMAC `download_url`. `GET /api/v1/files/{token}` answers with **307** to that upstream URL after the token and SSRF checks, so the video bytes do not pass through this process. `yt-dlp` resolves public videos, including YouTube, and downloads a file only when the source does not offer a direct URL. Private or removed videos are still rejected.

## Run locally

Go 1.22 or newer (1.27 is what this repo is built with) and, for social downloads, `yt-dlp` and `ffmpeg` on `PATH`.

```bash
cd backend
copy .env.example .env
go run ./cmd/api
```

The process listens on `$PORT`, or `8080` when `PORT` is unset.

```bash
go test ./...
go build -o socialsave-api ./cmd/api
```

## Deploy

`render.yaml` builds this directory with the Dockerfile. The container listens on `$PORT`. `SECRET_KEY` is generated by Render and must not be committed. Leave `PUBLIC_BASE_URL` unset on Render so signed links use `RENDER_EXTERNAL_URL` when the request host is local. `MAX_DOWNLOAD_BYTES` defaults to 256 MiB in code; the current Render config overrides it.

`OBJECT_STORAGE_URL`, when set, is an HTTP endpoint that accepts `PUT /{filename}` and then serves that object. Prepared jobs upload there and return that URL. With it empty, the temp file is served once from `/api/v1/files/{token}` and deleted.

## Configuration

See `.env.example`. Platform switches live in `ENABLED_PLATFORMS`. `REQUIRE_API_KEY=true` checks `X-API-Key` or `Authorization: Bearer` against `API_KEYS` on platforms, analyze, and download. Job status and file URLs stay unauthenticated because the id and HMAC token are the secrets.
